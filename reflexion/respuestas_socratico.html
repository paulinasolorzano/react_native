Hoja 1 de 4 El estado no se actualiza en pantalla (useState)
Escenario: El usuario escribe su nombre en un TextInput pero la pantalla no cambia porque el dato se guardó en una variable normal en lugar de un estado con useState.
1
¿Qué hace React Native cada vez que cambia un estado en tu componente?
Respuesta esperada
React Native vuelve a renderizar (redibujar) el componente automáticamente. Cuando un estado cambia, React detecta el cambio y actualiza la pantalla con el nuevo valor sin que el programador tenga que hacer nada extra.
2
Si guardas el nombre con let nombre = "" y luego haces nombre = "Carlos", ¿React Native se entera? ¿Por qué sí o por qué no?
Respuesta esperada
No. Una variable normal no está conectada al sistema de reactividad de React. Aunque el valor cambie en memoria, React no sabe que ocurrió ningún cambio y no redibuja la pantalla. La variable cambia "en silencio".
3
¿Cómo declararías correctamente el estado para guardar el nombre? Escribe la línea y explica qué hace cada parte.
Respuesta esperada
const [nombre, setNombre] = useState("")
• nombre → el valor actual del estado
• setNombre → la función para actualizarlo (dispara el re-render)
• "" → el valor inicial (cadena vacía al arrancar)
4
¿Qué prop del componente TextInput debes usar para actualizar el estado?
Respuesta esperada
onChangeText. Se ejecuta cada vez que el usuario escribe un carácter.
Uso: onChangeText={setNombre} o onChangeText={(texto) => setNombre(texto)}
Este prop "escucha" los cambios y los conecta al estado.
5
¿Cómo mostrarías el nombre en un componente Text? ¿Qué pasa si el estado está vacío?
Respuesta esperada
<Text>{nombre}</Text>
Si el estado está vacío (""), el componente Text simplemente no mostrará nada — no genera error. Es buena práctica poner un texto por defecto o un placeholder.
Conclusión esperada

useState es necesario porque React necesita "enterarse" de los cambios para actualizar la pantalla. Una variable normal no tiene esa capacidad — cambia en memoria pero la pantalla no se actualiza.

Hoja 2 de 4 El componente hijo no muestra la información (Props)
Escenario: Se creó un componente LugarCard pero aparece vacío porque los datos del lugar no se están enviando correctamente desde HomeScreen.
1
¿Dónde están los datos de los lugares y cómo los importas a HomeScreen?
Respuesta esperada
Los datos están en data.js (o similar). Se importan con:
import { lugares } from "../data";
Esta instrucción trae el arreglo de objetos para usarlo dentro de HomeScreen.
2
¿Qué son las props y en qué dirección fluyen?
Respuesta esperada
Las props son valores que un componente padre envía a un componente hijo al llamarlo. Fluyen en una sola dirección: de padre → hijo. El hijo recibe la información pero no puede modificarla directamente.
3
¿Cómo llamas a LugarCard desde HomeScreen pasándole el objeto lugar?
Respuesta esperada
<LugarCard lugar={item} />
• lugar → nombre de la prop (el "nombre del paquete")
• item → el objeto con los datos que se está enviando
4
¿Qué diferencia hay entre function LugarCard() y function LugarCard({ lugar })?
Respuesta esperada
function LugarCard() no recibe nada — aunque el padre envíe datos, el componente no puede acceder a ellos.
function LugarCard({ lugar }) desestructura las props y permite usar el objeto lugar directamente dentro del componente.
5
Dentro de LugarCard, ¿cómo mostrarías el nombre e imagen? ¿Qué pasa si lugar llega como undefined?
Respuesta esperada
<Text>{lugar.nombre}</Text>
<Image source={{ uri: lugar.imagen }} />
Si lugar llega undefined, la app arrojará un error al intentar acceder a .nombre. Se puede proteger con: lugar?.nombre
6
¿Puede LugarCard modificar directamente los datos que recibió por props?
Respuesta esperada
No. Las props son de solo lectura (inmutables) dentro del componente hijo. Si el hijo necesita provocar un cambio en el padre, el padre debe enviarle una función (callback) como prop para que el hijo la llame.
Conclusión esperada

Las props son el mecanismo de comunicación unidireccional entre componentes. Un componente reutilizable como LugarCard depende de recibir sus datos desde afuera para funcionar en distintos contextos sin repetir código.

Hoja 3 de 4 La lista FlatList aparece vacía
Escenario: Hay 8 lugares en data.js y se usó FlatList en HomeScreen, pero la pantalla aparece en blanco sin ningún error en consola.
1
¿Qué ventaja tiene FlatList sobre escribir componentes uno por uno manualmente?
Respuesta esperada
FlatList renderiza únicamente los elementos visibles en pantalla en cada momento (virtualización). Con listas grandes evita cargar todo de golpe, haciendo la app más fluida y eficiente en memoria. Escribir componentes manualmente implica repetir código y cargarlos todos al mismo tiempo.
2
¿Qué prop le indica a FlatList cuáles son los datos? ¿Qué tipo de valor recibe?
Respuesta esperada
El prop data. Debe recibir un arreglo (Array) de objetos:
data={lugares}
Si este prop está vacío [] o no se le pasa, FlatList no tiene qué mostrar.
3
¿Qué prop le dice cómo dibujar cada elemento? ¿Qué pasa si esa función no retorna nada?
Respuesta esperada
El prop renderItem. Debe retornar el componente visual de cada elemento:
renderItem={({ item }) => <LugarCard lugar={item} />}
Si la función no retorna nada, FlatList muestra filas vacías — no lanza error pero la lista se ve en blanco.
4
¿Para qué sirve keyExtractor? ¿Qué pasa sin él o con claves duplicadas?
Respuesta esperada
Asigna un identificador único a cada elemento para que React pueda rastrear cambios eficientemente:
keyExtractor={(item) => item.id.toString()}
Sin él o con claves duplicadas, React muestra advertencias en consola y puede renderizar mal los elementos al actualizar la lista.
5
Si los datos están en useState([]) y olvidaste actualizar el estado, ¿qué mostraría FlatList?
Respuesta esperada
Mostraría una lista vacía. FlatList solo ve el valor del estado ([] inicial) y no los datos de data.js, porque data.js no está conectado automáticamente al estado. Hay que cargar los datos con setLugares(datos).
6
¿Qué debe contener el arreglo de dependencias de useEffect para ejecutarse solo una vez?
Respuesta esperada
Debe estar vacío: useEffect(() => { setLugares(datos); }, [])
El arreglo vacío [] le indica a useEffect que solo debe ejecutarse cuando el componente se monta por primera vez — equivalente a "cargar al inicio".
Conclusión esperada

Flujo completo: datos en data.js → importar en HomeScreen → guardar en estado con useState → pasar al prop data de FlatList → FlatList dibuja cada elemento con renderItem → cada elemento recibe sus datos por props.

Hoja 4 de 4 La cámara y el GPS no funcionan (Permisos)
Escenario: Al presionar el botón de cámara o GPS la app se cierra inesperadamente o no hace nada, aunque las librerías están instaladas y el código parece correcto.
1
¿Por qué una app necesita pedir permiso antes de usar la cámara o el GPS?
Respuesta esperada
Por privacidad y seguridad del usuario. Sin ese control, cualquier app podría acceder al hardware del dispositivo sin que el usuario lo sepa — tomando fotos, grabando o rastreando su ubicación de forma silenciosa. El sistema operativo exige que el usuario autorice explícitamente cada acceso.
2
¿Qué función se llama para solicitar el permiso y de qué librería viene?
Respuesta esperada
Para imágenes/cámara (expo-image-picker):
await ImagePicker.requestMediaLibraryPermissionsAsync()
await ImagePicker.requestCameraPermissionsAsync()

Para GPS (expo-location):
await Location.requestForegroundPermissionsAsync()

Ambas devuelven un objeto con status: "granted" o "denied".
3
¿Qué debe hacer el código si el usuario niega el permiso?
Respuesta esperada
Mostrar un mensaje amigable explicando por qué la app lo necesita, sin crashear.
Ejemplo: Alert.alert("Permiso requerido", "Necesitamos acceso a la cámara...")
Nunca intentar usar la cámara o GPS si el permiso fue denegado — eso es lo que causa el cierre inesperado.
4
Para la cámara o galería: ¿qué función usas y cómo guardas la imagen?
Respuesta esperada
const result = await ImagePicker.launchImageLibraryAsync({ mediaTypes: "Images" });
if (!result.canceled) { setFoto(result.assets[0].uri); }
La URI apunta a la imagen en el dispositivo. Se guarda en estado para mostrarla con <Image source={{ uri: foto }} />.
5
Para el GPS: ¿qué función usas y dónde encuentras la latitud y longitud?
Respuesta esperada
const ubicacion = await Location.getCurrentPositionAsync({});
setLatitud(ubicacion.coords.latitude);
setLongitud(ubicacion.coords.longitude);
Las coordenadas están dentro de la propiedad coords del resultado.
6
¿Es mejor pedir el permiso en cada clic o una sola vez al cargar la pantalla? ¿Qué hook usarías?
Respuesta esperada
Una sola vez al cargar, usando useEffect con arreglo vacío:
useEffect(() => { solicitarPermisos(); }, [])
Así el usuario ve el diálogo de permiso solo al entrar a la pantalla por primera vez. Pedirlo en cada clic es mala experiencia de usuario y completamente innecesario.
Conclusión esperada

Pasos en orden: 1) Solicitar permiso al montar el componente (useEffect). 2) Verificar si fue concedido. 3) Si no → mostrar mensaje, no continuar. 4) Si sí → llamar a la función de cámara o GPS. 5) Guardar el resultado en un estado para mostrarlo en pantalla.
