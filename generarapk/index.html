1 Introducción

Hasta ahora has probado tu aplicación a través de Expo Go: escaneas un código QR, la app abre en el celular y puedes interactuar con ella. Sin embargo, esta forma de ejecutarla no es la versión final que un usuario instalaría en su celular — es solo una herramienta de desarrollo.

En esta práctica realizarás el proceso para compilar tu aplicación React Native en un archivo APK instalable de Android, usando el servicio en la nube EAS Build de Expo. Al terminar, tu app se podrá instalar en cualquier dispositivo Android sin necesitar Expo Go ni que tu computadora esté encendida.

Los bloques de código se presentan como imágenes con fondo blanco para que los escribas manualmente en la terminal. No los copies y pegues.

3 Conceptos clave
Concepto¿Qué es?¿Cuándo se usa?
Expo Go Aplicación móvil que permite probar proyectos Expo durante el desarrollo. Se conecta al servidor Metro de tu computadora mediante un código QR y ejecuta el código JavaScript en tiempo real. Solo durante el desarrollo. Nunca para distribución final.
EAS Build Servicio en la nube de Expo que compila el código React Native y genera archivos instalables. La compilación ocurre en servidores remotos de Expo; tu computadora solo envía los archivos y espera el resultado. Para generar la versión compilada de la app (APK, AAB o IPA).
EAS CLI Herramienta de línea de comandos que instala en tu computadora. Permite autenticarte con tu cuenta de Expo y enviar comandos de compilación a los servidores de EAS Build. En la computadora de desarrollo, antes y durante la compilación.
APK
Android Package		 Archivo instalable de Android. Equivale a un instalador .exe de Windows. Se puede descargar e instalar directamente en cualquier dispositivo Android sin pasar por la tienda. Pruebas internas, distribución directa entre personas conocidas. Esta práctica genera un APK.
AAB
Android App Bundle		 Formato de publicación para Google Play Store. Google recibe el AAB y genera APKs optimizados para cada tipo de dispositivo. No se puede instalar directamente como un APK. Publicación en Google Play Store.
IPA
iOS App Archive		 Equivalente al APK pero para dispositivos Apple (iPhone, iPad). No se puede instalar directamente en iOS por las restricciones de Apple; requiere pasar por App Store o TestFlight. Distribución en iOS vía App Store o TestFlight con cuenta Apple Developer.
Keystore Archivo de certificado digital que firma las aplicaciones Android. Funciona como la identidad del desarrollador: garantiza que los APKs de la misma app provienen del mismo autor. Android exige esta firma para instalar cualquier app. Obligatorio en toda compilación Android. Debe conservarse para poder publicar actualizaciones de la misma app.
Perfil de build Configuración definida en el archivo eas.json que indica cómo compilar la app. Puedes tener perfiles distintos: uno para generar APK de prueba (preview) y otro para generar AAB de producción (production). Se especifica al ejecutar eas build con la bandera --profile.

Antes de compilar, confirma que la app funciona sin errores en modo desarrollo. Si tiene errores al correr con Expo Go, la compilación puede fallar o la app compilada tendrá los mismos problemas.

Si hay errores en rojo: corrígelos antes de continuar. No tiene sentido compilar un APK de una app con errores.

EAS CLI es la herramienta de línea de comandos que se instala en tu computadora. Permite autenticarte con tu cuenta de Expo y enviar el proyecto a los servidores de EAS Build para compilarlo.

Paso 6Configurar EAS Build en el proyecto

Este comando debe ejecutarse desde la carpeta raíz del proyecto. Crea el archivo eas.json con los perfiles de compilación y vincula el proyecto local con tu cuenta de Expo.

Terminal — configurar EAS en el proyecto

El asistente hará varias preguntas interactivas. Responde de la siguiente manera:

Pregunta 1 — ¿Crear un proyecto EAS?
✅ Responde Y. Esto registra tu proyecto en expo.dev y permite monitorear las compilaciones desde el navegador.
Pregunta 2 — ¿Inicializar Git?
✅ Responde Y. EAS necesita que Git esté inicializado para identificar la carpeta raíz del proyecto. No es necesario haber hecho ningún commit; EAS sube tus archivos tal como están en la carpeta.
Pregunta 3 — ¿Crear archivo .gitignore?
✅ Responde Y. El archivo .gitignore le indica a Git qué carpetas ignorar, como node_modules, que puede pesar varios GB y no necesita subirse.
Pregunta 4 — ¿Para qué plataforma configurar EAS?
✅ Selecciona Android con las flechas del teclado y presiona Enter. Solo configuraremos Android en esta práctica.
¿Qué genera este comando? Crea el archivo eas.json en la raíz del proyecto. Ese archivo define los "perfiles" de compilación. El siguiente paso lo revisaremos para asegurarnos de que el perfil preview genera un APK y no un AAB.
Paso 7Verificar que Git está inicializado

EAS Build necesita que Git esté inicializado en el proyecto para identificar la carpeta raíz. Sin embargo, no es necesario haber hecho commits: EAS sube los archivos tal como están en tu carpeta de proyecto en ese momento.

Puedes verificar que Git está activo ejecutando:

Terminal — verificar que Git está inicializado
Salida normal (Git activo con cambios pendientes — no hay problema)
Si Git NO está inicializado — verás este error
Solución — inicializar Git
Aclaración técnica: EAS Build no compila desde tu historial de commits. Toma una copia de tus archivos actuales, los empaqueta y los sube a la nube. Git solo se necesita para que EAS identifique correctamente la raíz del proyecto.
7 Generación del APK Android
Paso 8Verificar el perfil APK en eas.json

El archivo eas.json generado puede usar app-bundle (AAB) por defecto. Para generar un APK instalable directamente, el perfil preview debe especificar "buildType": "apk".

Abre el archivo eas.json y verifica o ajusta su contenido para que quede así:

eas.json — configuración de perfiles
Explicación de perfiles:
· Perfil preview → genera APK. Para instalar directamente en Android sin pasar por la tienda.
· Perfil production → genera AAB. Para subir a Google Play Store cuando la app esté lista para el público.
Paso 9Generar el APK con EAS Build

Este es el comando principal. Sube el proyecto a los servidores de Expo para compilarlo. La compilación puede tardar entre 10 y 20 minutos dependiendo de la carga de los servidores.

Terminal — iniciar compilación APK para Android

Durante el proceso aparecerá la pregunta del Keystore:

Pregunta — ¿Generar un nuevo Android Keystore?
✅ Responde Y. Expo generará el Keystore y lo guardará de forma segura en tu cuenta de Expo en la nube.
⚠️ ¿Qué es el Keystore y por qué importa?
El Keystore es el certificado digital que firma la app. Android exige esta firma para instalar cualquier aplicación. Si perdieras el Keystore de una app ya publicada en Google Play, no podrías publicar actualizaciones de esa misma app; tendrías que publicarla como una app completamente nueva (con otro nombre de paquete).

Al responder Y, Expo genera y almacena el Keystore en tu cuenta de Expo automáticamente, por lo que queda respaldado sin que tengas que administrarlo tú mismo.

Después de confirmar el Keystore, la terminal mostrará el progreso y el enlace de monitoreo:

Salida esperada — enlace de seguimiento

Cuando la app esté lista para publicarse en Google Play Store, se usa el perfil production que genera un AAB en lugar de APK:

Terminal — generar AAB para Google Play
Diferencia práctica: el APK (perfil preview) lo instalas tú directamente en el celular para pruebas. El AAB (perfil production) lo subes a Google Play Console y es Google quien lo distribuye a los usuarios finales en forma optimizada.
8 Errores comunes y cómo resolverlos
Error / SíntomaCausa probableSolución
eas: command not found EAS CLI no se instaló o el PATH no está actualizado. Cierra y vuelve a abrir la terminal. Si persiste, ejecuta npm install -g eas-cli nuevamente.
Not logged in La sesión no se completó o expiró. Ejecuta eas login e ingresa tus credenciales de expo.dev.
fatal: not a git repository Git no está inicializado en el proyecto. EAS lo necesita para identificar la carpeta raíz. Ejecuta git init en la raíz del proyecto. No es necesario hacer commits; EAS sube tus archivos actuales directamente.
Android bloquea la instalación del APK Android bloquea por defecto apps de fuentes fuera de la tienda oficial. Configuración → Privacidad o Seguridad → Instalar apps de fuentes desconocidas → permite el navegador con el que descargaste el APK.
Build failed — SDK version mismatch La versión de Expo SDK en el proyecto no coincide con la configuración de EAS. Verifica que app.json tenga la versión de SDK correcta y que las dependencias en package.json correspondan a esa versión.
La compilación tarda más de 30 minutos Los servidores de Expo pueden estar con alta demanda. Es normal en horas pico. Monitorea el estado en expo.dev → Builds. Si marca error, reintenta el comando.
La app se instala pero inmediatamente se cierra Hay un error en el código JavaScript que no se detectó durante el desarrollo con Expo Go. Prueba la app en Expo Go primero y corrige todos los errores antes de compilar. Revisa que las variables de entorno necesarias estén correctamente configuradas para producción.
9 Nota sobre iOS

Para iOS, el proceso de compilación con EAS Build es técnicamente similar, pero la distribución es completamente diferente al modelo de Android:

  • En Android puedes instalar el APK directamente descargándolo desde cualquier enlace.
  • En iOS no existe el equivalente de instalación directa. Todo debe pasar por canales oficiales de Apple.
  • Para distribuir en iOS se requiere una cuenta de Apple Developer ($99 USD/año).
  • Para pruebas internas se usa TestFlight. Para distribución pública, la App Store.
  • Apple revisa cada versión antes de aprobarla para distribución.
Terminal — compilar para iOS (referencia)
En esta práctica solo trabajamos Android. La nota sobre iOS es únicamente informativa para que conozcas las diferencias entre plataformas.
